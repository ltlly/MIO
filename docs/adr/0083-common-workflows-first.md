# ADR-0083：先完成常用工作流，再补低频增强

- 日期：2026-11-09。
- 状态：已实施（Batch A → Batch P 已按此顺序全部交付）。
- 补充 ADR-0081／0082；技术路线、最终兼容、安全与质量合同不变。

此前把“项目兼容优先”执行成持续补齐注解、时间等字段，又在基本纯文本 Notes 可用后投入富文本编辑器，挤占了 HTTP 历史筛选、Intruder 结果分析和常用发送设置。用户要求先评估每项功能的使用价值与优先级，先完成常用能力。

基本项目新建／打开／保存／另存为／重开及 schema229 HTTP／Repeater 导入已交付。后续以“外部客户端抓包 → 找到目标请求 → 修改并重放 → 批量测试并定位异常 → 取消及保存恢复”作为首要操作链，而不是要求所有外部归档字段映射完成后才继续工具开发。

排序依据依次为：数据丢失／错误发送等已确认风险；缺失是否阻断核心操作；在日常流程中的出现频率；当前是否已有可用替代操作；实现和验证成本、依赖是否就绪。实现容易或探针已有线索不能单独构成高优先级；成本用于同等收益之间取舍，不能以低成本项目替代必需能力。

后续演进与模块拆分规划统一维护在 [ROADMAP](../ROADMAP.md)。已完成的底层、保存点及试用包保留，只补受影响的回归。Notes 富文本在途源码、测试与证据冻结保留，未通过部分不进入试用包；不为收尾低收益原型继续扩展通用编辑器。

每个交付仍须验证其真实入口、保存恢复、取消、错误保留、二进制／重复字段及必要 IME／焦点／剪贴板行为；明显卡顿、遮挡或误操作属于功能缺陷，不能后置。完整像素、全场景性能、长尾格式／协议与插件验收继续是最终目标，按使用价值分期完成，不能用优先级降低来宣称它们已实现或已取消。
