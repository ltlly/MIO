# ADR-0082：外部项目归档兼容与质量硬约束

- 日期：2026-11-04。
- 状态：已实施。
- 演进说明（2026-11-15）：本记录第 1 节早期的单平台范围已由 [ADR-0084](0084-cross-platform-ui-and-static-packaging.md) 正式扩展为 **macOS + Windows + Linux** 跨平台原生支持；其余外部归档只读转换、UI/行为一致性与性能测试硬约束继续有效。
- 补充 [ADR-0081](0081-rust-gpui-clean-start.md)，覆盖早期材料中关于单平台首发或粗粒度兼容的表述。

## 1. 平台与工作方式

Rust + GPUI/Kit、Rama + Rustls/ring、零 Python、强原生插件、不做内嵌测试浏览器的技术方向保持不变。
实现坚持最小完整实现与优先复用，不以“简化”为由削减功能、兼容性或数据完整性要求；修改前明确模块与共享协议归属，不夹带未完成改动，不提交敏感测试样本或私钥。

## 2. 外部项目归档兼容与自有落盘

必须支持常见二进制安全测试项目归档（`schema 228 / 229`）的只读识别、流式导入与后续工作流衔接，转换为 MIO 自有 `.mio` SQLite/WAL 项目格式。
HAR/XML/单条请求导入可作为补充，但不替代项目归档导入；同时明确不执行外部遗留 JVM/JAR/Jython 插件。

导入路径必须保持源归档文件绝对只读，支持取消、原子落盘与失败恢复，绝不覆盖原文件、静默丢失字段或自动向外部目标发起请求；未映射的专有槽位通过 `ExtCoverageReport` 明确汇报，不将部分映射包装为全量兼容。不支持无证双向写回或伪造外部格式文件。

自有 `.mio` 格式兼顾打开速度与体积控制：基于 SQLite WAL 分离元数据索引与压缩正文，按需懒加载载荷并支持 `SlimSaveProjectAs`（清理冗余流量并执行 `VACUUM`）。不得以丢弃正文、截断历史、遗漏工作区状态或隐匿 sidecar 换取基准数字。

## 3. 原生 UI 精度、设置与上下文菜单

除简体中文文案与垂直标签组外，桌面工作台坚持逐像素级别视觉规范与全套设置／右键菜单一致可用：完整实现所有菜单分组、排序、分隔线、快捷键、可用条件、单选/多选语义与实际动作，不允许静态空壳或占位菜单。所有设置项的默认值、依赖联动、生效时机与应用/取消/重置语义须有完整后端联动与测试覆盖。

对于字符集解析与 URL 编解码等边界场景，遵循字节保留原则并修正不合理的截断或静默替换行为（例如含 UTF-8/中文的 URLDecode）。

## 4. 性能与资源效率

在桌面环境下确保冷/暖加载、首屏可交互、连续抓包吞吐、筛选/排序/搜索响应、编辑与软折行滚动延迟、大报文与超长单行承载、任务取消上界及内存/磁盘占用持续受控；以无丢包、无功能降级的真实可复现样本开展测量。

## 5. 测试选择和十分钟预算

日常迭代针对受影响模块及回归边界运行验证；集成与交付前运行完整自动化测试套件。
**完整自动化测试从统一入口（`scripts/test.sh`）启动到全部退出的 wall time 必须 ≤10 分钟**，包含夹具创建、测试执行与子进程/连接清理；不允许通过 skip、放宽关键断言或剔除慢测试来掩盖退化。

## 6. 零占位与交付

不交付静态 UI 壳、空操作 handler、演示数据或永久禁用菜单；空态、错误、只读与忙碌状态必须真实闭环，功能边界见 [架构文档](../architecture.md)。
